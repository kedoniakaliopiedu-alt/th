# Лист правок — критерий закрытия темы

Источник: штурм 28.07.2026, `.memlog.md` (118 записей, 102 идеи).
Правки не внесены — это задание для `skill-writer`.

**Суть.** У темы появляется состояние и проверяемое условие перехода в «закрыта».
Закрытая тема уходит из спирали в редкий контроль, но не исчезает. Откат назад мягкий.
Механизм собирается из уже написанных частей проекта — принципиально нового кода мало.

Порядок важен: правка 1 (оживить шкалу) должна идти первой, иначе всё остальное
встанет на мёртвое основание.

---

## 1. `progress.json` — структура данных

**1.1. Оживить mastery.** Сейчас mastery растёт только при `consecutive_correct >= 5`,
и по факту у всех восьми тем он равен 0 при 429 элементах. Снизить порог (кандидат: 3
верных подряд) либо считать mastery от `repetitions`, а не от серии подряд.
*Сигнал, что сработало:* в `tracker.py progress` у тем появляются ненулевые значения,
различающиеся между темами.

**1.2. Новый раздел `topics`** рядом с `items` и `mistakes`. Ключ — номер темы («3.4»).
Поля:

```json
"3.4": {
  "title": "Распорядок дня",
  "status": "in_progress",          // no_criterion | in_progress | testing | closed | returned
  "exit_task": "...",               // что нужно уметь; берётся из файла темы
  "core": ["ตื่น", "อาบน้ำ", "..."],  // ядро темы, 15–20 элементов
  "attempts": [{"date":"...","result":"ok|fail","accuracy":0.0,"blocked_by":[]}],
  "closed_on": null,
  "reopened_on": null,
  "next_control": null,             // дата редкого контрольного повтора
  "closed_at_difficulty": null,     // на каком уровне сложности закрыта
  "suspicion": 0                    // ошибок по закрытой теме: 1 — подозрение, 2 — переоткрытие
}
```

**1.3. Средний mastery темы считать по медиане плюс доле элементов с `repetitions >= 2`,
а не по среднему арифметическому.** Среднее прячет мёртвый хвост: 60 сильных элементов
и 20 нулевых дают проходной балл.

## 2. `thai-tasks/scripts/tracker.py` — команды

**2.1. `topics <progress.json>`** — таблица состояний всех тем: статус, уровень, что
мешает закрыть. Печатается словами, без звёздочек и процентов.

**2.2. `close <progress.json> <тема> --result ok|fail [--accuracy N]`** — фиксирует
попытку закрытия, дописывает `attempts`, пересчитывает `status`.

**2.3. `blockers <progress.json> <тема>`** — что именно мешает закрыть, **не длиннее трёх
пунктов**. Это ответ на вопрос «почему тема не закрывается», без него механизм
непрозрачен.

**2.4. Побочные эффекты существующих команд:**
- `mistake ... --topic X` — снимает у темы X право на закрытие; если тема закрыта,
  поднимает `suspicion` (1 → подозрение, 2 → `returned`);
- `record` с качеством < 3 по элементу закрытой темы — то же самое;
- `import` — заводит запись темы в `topics` со статусом `in_progress`, а при отсутствии
  секции exit-задания в файле темы — со статусом `no_criterion`.

**2.5. Ядро темы.** Если в файле темы ядро не размечено — брать первые 15–20 элементов
импорта, правила (`type: rule`) включать в ядро всегда (грамматика в приоритете по плану
B1).

*Сигнал, что сработало:* `topics` показывает разные статусы у разных тем, `blockers 3.4`
выдаёт конкретные причины, а не пустоту.

## 3. `thai-tasks/references/progress-and-spiral.md`

**3.1. Новый раздел «Состояния темы и закрытие».** Пять состояний и переходы:

```
нет критерия → в работе → на испытании → закрыта → вернулась
                   ↑                                    │
                   └────────────────────────────────────┘
```

**3.2. Ворота закрытия — шесть условий, все обязательны:**

1. **Пауза** — не меньше 7 дней с последнего занятия по теме. Считать и в днях, и в
   занятиях: при занятиях раз в месяц эти два счётчика ведут себя по-разному.
2. **Только продукция** — в закрывающем испытании запрещены выбор из вариантов и
   перевод тай→рус.
3. **Без подсказок** — использованная подсказка обнуляет попытку.
4. **Ноль активных ошибок** с меткой этой темы: ни одного паттерна `active` / `critical`.
5. **Порог по худшему, а не по среднему**, и считается по ядру темы, а не по всем
   элементам.
6. **Совпадение с калибровкой** — верный, но помеченный «не уверена» ответ идёт как
   качество 3 и не закрывает.

**3.3. Правило двух кругов на закрытие.** Одного успешного испытания мало: второе через
интервал. Механика уже описана для ошибок — переиспользовать её, не изобретать вторую.

**3.4. Поведение спирали после закрытия.** Тема выпадает из `get_due` как источник
собственных заданий, но:
- уходит в редкий контроль: 90 → 180 → 365 дней;
- её лексика становится **обязательным фоном** в заданиях по другим темам;
- слова продолжают жить в SM-2 независимо от статуса темы (одно слово может
  принадлежать двум темам — закрывается тема, а не слова).

**3.5. Откат.** Первая ошибка по закрытой теме — подозрение, вторая — переоткрытие.
Переоткрытая тема входит **не на старт**, а в режим отработки по тому паттерну, который
её уронил.

**3.6. Срок годности.** Закрытие привязано к уровню сложности: поднялась
`meta.difficulty` — темы, закрытые на низком уровне, переходят в «требует
переподтверждения».

## 4. `thai-tasks/SKILL.md`

**4.1. В «С чего всегда начинать»** — шаг: прочитать статус темы из `topics` до
генерации. Тема со статусом `closed` не берётся в работу как новая; запрос по ней —
это либо контроль, либо переоткрытие.

**4.2. В раздел «Режим C — срез/контрольная»** — закрывающее испытание есть частный
случай среза: покрытие одной темы, без подсказок, с калибровкой до. Отдельный формат не
вводить.

**4.3. В «Итог занятия и домашку»** — одна строка о движении темы к закрытию:
«Тема 3.4 ближе к закрытию: осталось снять ошибку со счётными словами». Без
поздравлений, счётчиков и достижений — тон проекта запрещает геймификацию.

**4.4. В чеклист перед выдачей** — пункт: статус темы проверен, закрытые темы не
подмешиваются как новые.

## 5. `thai-mistakes/SKILL.md`

**5.1. Калибровка перед закрывающим испытанием.** Механика калибровки уже принадлежит
этому скиллу — расширить её на закрытие: «считаешь тему закрытой, и сколько сдашь?».
Расхождение прогноза и результата пишется отдельно.

**5.2. Разметка неуверенного.** Ученица помечает пункты испытания, где не уверена
(механика взята из `thai-handwriting`). Помеченный верный ответ не закрывает тему.

**5.3. Право оспорить.** «Не чувствую, что закрыла» — тема возвращается в работу,
расхождение записывается как калибровочный сигнал, а не игнорируется.

**5.4. Ловушка в испытании.** Закрывающее испытание обязано содержать контрпример на
типичное заблуждение по теме (`references/misconceptions.md`).

## 6. Файлы тем — `Thai A2/`, `Thai B1/`

**6.1. Новая секция в конце файла темы:**

```markdown
## Тема закрыта, если ты можешь

1. ...
2. ...
3. ...
```

3–5 действий, сформулированных как действия, а не как знания («заказать две порции риса
и уточнить остроту», не «знать счётные слова»).

**6.2. Писать эту секцию при создании темы, до занятий по ней** (обратное
проектирование): движок должен знать цель заранее.

**6.3. Разметка ядра** — ключевые элементы отмечаются в списке лексики.

**6.4. Уже написанные темы** (A2 главы 1–7, B1 главы 1–2) секции не имеют. Дописывать
задним числом — отдельная работа; до этого они получают статус `no_criterion`, и это
честно видно в `topics`.

одна-две темы.
