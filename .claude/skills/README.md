# Скиллы проекта Thai

Набор скиллов, превращающих Claude в персонального репетитора по тайскому для этого
репозитория. Практико-ориентированное обучение: осознанные комплексные задания, спираль
с интервальным повтором, продукция рус→тай, серьёзный тон без геймификации.

Скиллы делятся на два слоя. **Учебные** (`thai-*`, `learn`, `teach`) ведут занятие.
**Мета-скиллы** (`skill-*`) обслуживают сам инструмент: придумать механику, написать
документ, отревьюить написанное. Учебный слой — про тайский, мета-слой — про репозиторий;
путать их не надо, у каждого мета-скилла в `description` прямо сказано, чем он **не**
является.

## Состав и роли

| Скилл | Роль |
|---|---|
| **thai-tasks** | Главный движок. Собирает комплексные практические задания по любой теме, ведёт трекер прогресса (SM-2), спираль 60/40, три режима (сессия / воркшит / срез). |
| **thai-mistakes** | Второй такт занятия: калибровка самооценки до вердикта, отчёт по проверенному листу (✅/🟡/❌), запись ошибок в трекер, отработка целой темы в режиме под тип ошибки, контрпример против заблуждений, правило двух кругов. |
| **thai-learning** | Правила подачи заданий и проверки ответов, структура уровней, контрольные. |
| **thai-phonetics** | Кириллическая транскрипция тайских звуков, тоновые знаки (` ˆ ´ ˇ). |
| **thai-display** | Оформление слов по классам согласных. Опционально — только когда нужен разбор по классам. |
| **thai-handwriting** | Чтение тайского с картинок, прежде всего рукописного: фото тетради, доска, вывеска. Конвейер «предобработка → нарезка на строки → чтение → орфографические фильтры → словарь». |
| **learn** | Базовая педагогика: диагностика, один шаг за ход, подсказка вместо готового ответа. |
| **teach** | Учебное пространство: миссия, learning-records, ресурсы, глоссарий (форматы). |

Мета-слой — работа над самим инструментом:

| Скилл | Роль |
|---|---|
| **skill-brainstorm** | Мозговой штурм по механикам скиллов и форматам заданий. Три стойки (фасилитатор / со-творец / придумай за меня), каталог из 122 техник, журнал сессии на диске, возобновление. |
| **skill-review** | Состязательное ревью скиллов, справочников, скриптов и учебных файлов: параллельные слепые слои + структурированный триаж. |
| **skill-writer** | Техписатель: написать документ, проверить по стандарту, объяснить механизм, собрать mermaid-схему. |

## Как связаны

Точек входа три, каждая срабатывает по своему поводу; ниже — на что опирается каждая.

```
thai-tasks        ← просят задания, тренировку, практику
├── learn            — педагогика диалога
├── thai-learning    — правила подачи и проверки
├── thai-phonetics   — транскрипция и тоны
└── thai-display     — оформление по классам (опционально)
        │
        ↓ проверил ответы — передаёт ход
        │
thai-mistakes     ← проверены ответы; или прямой запрос «разбери ошибки»
├── thai-tasks       — трекер, каталог заданий, правила генерации
├── thai-learning    — правила проверки
└── thai-phonetics   — транскрипция

thai-handwriting  ← в сообщении изображение
├── thai-phonetics   — транскрипция прочитанного
├── thai-learning    — разбор языковых ошибок в рукописной работе
├── thai-display     — оформление разобранных слов
└── thai-tasks       — трекер: записать повторяющийся дефект почерка
```

Стрелка `tasks → mistakes` — передача хода, а не подчинение: обратная связь сильнее,
`thai-mistakes` берёт у движка трекер, каталог заданий и правила генерации.

`teach` в схеме нет намеренно: это вендорный скилл (Matt Pocock), закрытый от
автовызова (`disable-model-invocation: true`). Его практики — миссия, learning-records,
ресурсы — переписаны под проект в `thai-tasks/references/mission-and-records.md`, и
движок обращается туда, а не к самому скиллу.

Мета-слой замкнут в свой цикл и с учебным не пересекается:

```
skill-brainstorm  ← «давай поштурмим», «накидай идей», «придумаем формат»
        │  лист правок (.claude/brainstorms/<тема>/изменения.md)
        ↓
skill-writer      ← «напиши скилл», «перепиши SKILL.md», «объясни, как устроено»
        │  написанные файлы
        ↓
skill-review      ← «отревьюй мои правки», «аудит thai-tasks»
        │  отчёт (.claude/reviews/) + находки, которые тянут на переделку
        └──────────→ обратно в brainstorm или writer
```

Цикл не обязателен: любой из трёх запускается сам по себе. Штурм ничего не правит,
писатель ничего не решает за автора, ревью ничего не пишет без явного выбора.

## Источник теории

Материал уроков лежит в этом же репозитории:

- `Thai A2/Chapter N/glavaN_temaM_*.md`
- `Thai B1/Chapter N/b1_glavaN_temaM_*.md`
- `Helpers/*.md` — доп. справки (напр. направительные частицы)

thai-tasks ищет файлы **рекурсивно** и берёт из них лексику и правила (примеры из секции
«Практические упражнения» не переписывает — генерирует свежие).

## Трекер прогресса

thai-tasks ведёт `progress.json` (в корне проекта) через скрипт
`thai-tasks/scripts/tracker.py` — только стандартная библиотека Python 3.8+, офлайн.

```bash
# импортировать словарь темы
python3 .claude/skills/thai-tasks/scripts/tracker.py import progress.json "Thai A2/Chapter 3/glava3_tema4_rasporyadok.md" --topic 3.4
# что пора повторить
python3 .claude/skills/thai-tasks/scripts/tracker.py due progress.json
# применить SM-2 после ответа (качество 0–5)
python3 .claude/skills/thai-tasks/scripts/tracker.py record progress.json "ตื่น" 5
# записать паттерн ошибки
python3 .claude/skills/thai-tasks/scripts/tracker.py mistake progress.json "тон_финаль" --category Тоны --topic 3.4 --your ... --correct ...
# план работы над ошибками (темы, режимы, объём) и итог круга отработки
python3 .claude/skills/thai-tasks/scripts/tracker.py drill-plan progress.json
python3 .claude/skills/thai-tasks/scripts/tracker.py attempt progress.json "тон_финаль" --result ok
# обзор прогресса
python3 .claude/skills/thai-tasks/scripts/tracker.py progress progress.json
```

Полная механика (SM-2, get_due, база ошибок, авто-импорт, регулятор сложности) —
в `thai-tasks/references/progress-and-spiral.md`.

## Распознавание письма

Весь инструментарий thai-handwriting работает офлайн. Основной путь — на встроенном в
macOS, ставить ничего не надо:

```bash
S=.claude/skills/thai-handwriting/scripts

$S/intake                                                              # фото из буфера → Handwriting/ + нарезка
$S/thaiocr lines фото.jpg /tmp/th --scale 4 --words-from progress.json  # нарезать на строки
$S/thaiocr prep  фото.jpg /tmp/clean.png --deskew --mono --scale 2      # выпрямить и почистить
$S/thaiocr crop  фото.jpg /tmp/zoom.png --rect 400,120,300,90 --scale 6 # приблизить фрагмент
python3 $S/lookup.py "?ับ"                                             # кандидаты по словарю
$S/clean                                                               # очистить Handwriting/ («clean photo»)
```

`thaiocr` — Swift поверх Vision (OCR `th-TH`) и CoreImage (предобработка), собирается сам
при первом запуске. Vision силён на печати и ненадёжен на рукописи, поэтому основной режим
— `lines`: страница режется на строки с апскейлом, и каждая читается отдельно.

Есть **второй движок** — `thai-handwriting/scripts/typhoon.py` (Typhoon OCR 1.5 через
локальный Ollama), для
независимой перекрёстной проверки на всей странице. На этом почерке он замерен слабее
Vision, поэтому истиной не считается; детали и замеры — в
`thai-handwriting/references/calibration.md`.

## Как пользоваться

Запусти движок и назови тему любого масштаба:

```
/thai-tasks составь задания на тему Глава 3 · Тема 3.4 — Распорядок дня
/thai-tasks потренируем счётные слова
/thai-tasks дай разговорную практику на рынке
/thai-tasks покажи прогресс
```

Масштаб запроса управляет объёмом: правило (≤5, разминка+сборка) → подтема (все блоки) →
тема (сборник подтем) → глава (план по темам).

## Работа над ошибками

После проверки любых заданий включается **thai-mistakes**:

0. калибровка — один вопрос **до** показа вердикта: сколько, по-твоему, верно и что
   угадала. Уверенная ошибка идёт в отработку первой, угаданное попадание пишется в
   трекер как качество 3, а не 5;
1. отчёт по всему листу — задания как были, к ним ✅ / 🟡 / ❌, верный вариант и строка
   «почему», внизу сводка N/Y, %, разбивка по категориям и строка калибровки;
2. ошибки уходят в `progress.json` с темой;
3. мини-диагностика темы (3–5 вопросов) — где ещё дыры;
4. пояснение правила от твоей ошибки и блок отработки: 3 задания за первую ошибку темы,
   +1 за каждую следующую, потолок 10. Если ошибка системная — сначала контрпример:
   случай, где твоё правило само себя опровергает;
5. режим подбирается по типу ошибки: запоминание слов / тоновый дрилл / трансформации /
   восстановление написания / регистр и уместность;
6. ошибка снята, когда ты и сформулировала, что было не так в старом рассуждении, и
   прошла новый случай-ловушку. Одних верных ответов мало;
7. ошибка повторилась — второй круг, пересобранный (правило индуктивно, шаги мельче).
   Не снялась и там — на следующее занятие первым номером, статус `critical`.

Справочные файлы: `thai-mistakes/references/report-format.md` (формат отчёта),
`thai-mistakes/references/drill-modes.md` (режимы отработки),
`thai-mistakes/references/misconceptions.md` (типы заблуждений, метод контрпримера,
критерий закрытия).

## Справочные файлы thai-tasks

- `thai-tasks/references/exercise-catalog.md` — меню типов заданий (атомарные → интеграционные →
  комплексные), включая индуктивный вывод правила, этимологию/морфемы, нарративы.
- `thai-tasks/references/checking.md` — порядок разбора: подсказки → ответ, оценка по 4 категориям
  (Словарь / Грамматика / Орфография / Тоны), линза «естественность», сверка тонов.
- `thai-tasks/references/progress-and-spiral.md` — трекер, SM-2, спираль, авто-импорт, регулятор
  сложности 1–10, целевой успех 60–70%.
- `thai-tasks/references/output-format.md` — оформление листа (буквенные блоки, нумерация, списки,
  подача лексики, транскрипция) и чеклист однозначной формулировки задания.
- `thai-tasks/references/speaking-and-live.md` — разговорная практика текстом и живой материал из
  браузера (Claude in Chrome).
- `thai-tasks/references/mission-and-records.md` — миссия, learning-records, доверенные источники.

## Мета-слой: работа над скиллами

Три скилла обслуживают сам инструмент. Адаптированы из
[BMAD Method](https://github.com/bmad-code-org/bmad-method) (MIT); что именно взято и что
переписано — в `ATTRIBUTION.md` каждого скилла.

```
/skill-brainstorm придумаем форматы заданий на счётные слова
/skill-writer     перепиши SKILL.md у thai-display
/skill-review     аудит thai-tasks
```

**skill-brainstorm.** Сессия идёт в одной из трёх стоек: фасилитатор (своих идей не
подкидывает, только выжимает твои), со-творец (кидает свои, помечая авторство), придумай
за меня (проводит всё сам и показывает результат). Стойка и набор техник выбираются на
офлайн-странице-композере, её надо открыть и вставить результат обратно в чат:

```bash
S=.claude/skills/skill-brainstorm
open $S/assets/brain-selector.html                       # выбрать стойку и техники

# пересобрать страницу, если правил каталог
python3 $S/scripts/brain.py --extra $S/assets/extra-techniques.json \
  html --out $S/assets/brain-selector.html

python3 $S/scripts/brain.py --extra $S/assets/extra-techniques.json categories
python3 $S/scripts/brain.py --extra $S/assets/extra-techniques.json list --category методика
```

Каталог — 108 общих техник из BMAD плюс 14 своих в категории **«методика»**
(`assets/extra-techniques.json`): «Инверсия ошибки», «Обратная спираль», «Провал скилла»,
«Триггерный стресс-тест» и другие, написанные под проектирование заданий и скиллов.
Ход сессии пишется в `.claude/brainstorms/<тема>-<дата>/.memlog.md` — сессия переживает
обрыв и возобновляется с того же места.

**skill-review.** Шесть слоёв, каждый — подагент без контекста разговора: слепой охотник
(противоречия и неоднозначности), охотник за краями (что будет, если материала нет или
ученица отвечает не так), разрыв проверяемости, границы скиллов (нарушения `CLAUDE.md` и
захват чужой зоны), методический аудитор (три опоры `thai-tasks`), ревьюер скриптов.
Слои правятся в `references/review-layers.md`, не трогая сами шаги. Находки проходят
триаж — дедуп, чтение файла **до** присвоения важности, маршрут в «решение / правка /
отложить / шум» — и ложатся в `.claude/reviews/`.

**skill-writer.** Четыре операции: написать документ, проверить по стандарту, объяснить
механизм, собрать mermaid-схему. Домашний стандарт документации — в
`references/skill-doc-standards.md`: контракт `description` (включая обязательное «когда
НЕ использовать»), прогрессивное раскрытие через `references/`, чеклист в конце `SKILL.md`,
запрет на утечку методической кухни в текст для ученицы.

## Примечания

- Транскрипция — строго кириллицей; тоновый знак ставится над гласной.
- Тоны перед оценкой сверяются по авторитетному источнику (thai-language.com), не по памяти.
- Литовские скиллы (`lithuanian-*`) относятся к отдельному проекту LT и здесь не нужны.
