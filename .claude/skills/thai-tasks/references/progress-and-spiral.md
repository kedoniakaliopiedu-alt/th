# Трекер прогресса, SM-2 и спираль

Механика собрана из практик двух плагинов и адаптирована под осознанную практику Ked:
- из **polyglot** — идея mastery-уровней и авто-импорта сид-словаря;
- из **fluent** — алгоритм **SM-2** (интервал по easiness-factor) и **база ошибок-
  паттернов** с примерами.

Скилл читает и переписывает один файл `progress.json` в проекте Thailand. Геймификации
(стрики, ачивки) нет — тон серьёзный, фокус на обучении.

## Автоматизация: scripts/tracker.py (основной путь)

Чтобы не считать SM-2 и get_due вручную, **используй бандл-скрипт** `scripts/tracker.py`
(только стандартная библиотека Python 3.8+). Он сам создаёт/обновляет `progress.json`.
Путь к progress.json — в проекте Thailand (например `<проект>/progress.json`).

```
# начать тему: импортировать её словарь из файла главы
python3 scripts/tracker.py import <progress.json> <glavaN_temaM_*.md> --topic 6.1

# что повторить (для 40% спирали) — вернёт JSON: mistakes_due + items_due + background
python3 scripts/tracker.py due <progress.json> --limit 4

# после ответа: применить SM-2 (quality 0–5)
python3 scripts/tracker.py record <progress.json> "ข้าว" 5
python3 scripts/tracker.py record <progress.json> "счётные слова จาน/ที่" 2 --type rule --topic 6.1.2

# записать паттерн ошибки (--topic обязателен: по нему собирается работа над ошибками)
python3 scripts/tracker.py mistake <progress.json> "тон_высокий_класс_закрытый" \
    --category Тоны --topic 6.1 --your средний --correct нисходящий --context "ข้าว"
# закрыть паттерн, когда он стабильно без ошибок
python3 scripts/tracker.py resolve <progress.json> "тон_высокий_класс_закрытый"

# работа над ошибками (skill thai-mistakes): список паттернов, план дрилла, итог круга
python3 scripts/tracker.py mistakes <progress.json> --topic 6.1
python3 scripts/tracker.py drill-plan <progress.json>
python3 scripts/tracker.py attempt <progress.json> "тон_высокий_класс_закрытый" --result ok

# состояния тем и критерий закрытия (см. «Состояния темы и закрытие»)
python3 scripts/tracker.py lesson <progress.json> 3.4     # отметить занятие по теме
python3 scripts/tracker.py topics <progress.json>
python3 scripts/tracker.py blockers <progress.json> 3.4
python3 scripts/tracker.py close <progress.json> 3.4 --result ok \
    --production --no-hints --calibrated --accuracy 0.9

# обзор прогресса (для «покажи прогресс»)
python3 scripts/tracker.py progress <progress.json>

# сложность/точность
python3 scripts/tracker.py set-meta <progress.json> --difficulty 5 --recent-accuracy 0.68
```

Рабочий цикл занятия: `import` (если новая тема) → `due` (взять повтор в спираль) →
генерация и проверка заданий → по каждому элементу `record`, по ошибкам `mistake` →
`lesson` (отметить занятие по теме) → в конце `progress` и, при желании, `set-meta`.

Если Python почему-то недоступен — веди `progress.json` вручную по формулам ниже (скрипт
реализует ровно их). Формулы остаются источником истины.

## progress.json — структура

```json
{
  "meta": {
    "difficulty": 4,
    "target_success": [0.6, 0.7],
    "recent_accuracy": 0.0,
    "updated": "2026-07-21"
  },
  "items": {
    "ข้าว": {
      "translation": "рис", "translit": "кхаау", "type": "word", "topic": "6.1",
      "repetitions": 2, "interval_days": 6, "easiness_factor": 2.5,
      "due_date": "2026-07-27", "last_seen": "2026-07-21",
      "mastery": 2, "consecutive_correct": 2, "consecutive_incorrect": 0
    },
    "счётные слова จาน/ที่": {
      "translation": "классификаторы порций", "translit": "", "type": "rule", "topic": "6.1.2",
      "repetitions": 0, "interval_days": 1, "easiness_factor": 2.3,
      "due_date": "2026-07-22", "last_seen": "2026-07-21",
      "mastery": 1, "consecutive_correct": 0, "consecutive_incorrect": 1
    }
  },
  "mistakes": {
    "тон_закрытый_слог_высокий_класс": {
      "category": "Тоны", "topic": "6.1", "frequency": 3, "status": "active",
      "rounds": 1, "drill_ok": 0, "last_drill": "2026-07-21",
      "last_occurred": "2026-07-21", "next_review": "2026-07-22",
      "examples": [
        { "your_answer": "средний", "correct_answer": "нисходящий",
          "context": "ข้าว", "date": "2026-07-21" }
      ],
      "notes": "путает нисходящий и средний на ข-словах с ไม้โท"
    }
  },
  "topics": {
    "3.4": {
      "title": "Распорядок дня", "status": "in_progress",
      "exit_task": "Рассказать свой день с временем и ответить на вопрос о распорядке",
      "core": [], "last_lesson": "2026-07-20", "last_shake": "",
      "attempts": [
        { "date": "2026-07-20", "result": "ok", "accuracy": 0.9,
          "counted": true, "voided": false, "blocked_by": [] }
      ],
      "closed_on": null, "reopened_on": null,
      "next_control": null, "control_step": 0,
      "closed_at_difficulty": null, "suspicion": 0
    }
  }
}
```

- `items` — и лексика (`word`), и правила/конструкции (`rule`/`construction`).
  Для Ked грамматика в приоритете (её план B1), поэтому правила отслеживаем наравне.
  Ключ элемента хранится в **нормализованной форме NFC**: тайские тоновые знаки и нижние
  гласные переставляются нормализацией, и одно слово, набранное в разном порядке, иначе
  давало бы два ключа с расходящимся mastery. Скрипт нормализует ключ на входе и при
  загрузке сводит уже накопленные дубли к одному: историю (`repetitions`, `mastery` и
  прочие счётчики) берёт у той записи, где её больше, а пустые `translation`, `translit`
  и `topic` добирает у второй. Выбрасывать проигравшую карточку целиком нельзя — так
  терялся перевод, и слово оставалось в выдаче, но собрать по нему задание было уже не из
  чего. При ручном ведении файла правило то же.
- `topics` — состояние каждой темы и критерий её закрытия (раздел «Состояния темы и
  закрытие»). Ключ — номер темы, ровно тот же, что в `topic` у элементов и ошибок.
- `mistakes` — повторяющиеся ошибки как **паттерны**, категория ровно из 4 категорий
  проверки (Словарный запас / Грамматика / Орфография / Тоны) — плюс отдельно
  «Регистр/обращения» и «Терминология», у них свои режимы отработки.
- Поля работы над ошибками (ведёт skill **thai-mistakes**): `topic` — тема, по которой
  собирается дрилл; `rounds` — сколько кругов отработки прошло; `drill_ok` — успешных
  кругов подряд (два подряд → `resolved`); `last_drill`; `status` = `active` /
  `critical` (пережила два круга за занятие, идёт первой в спирали) / `resolved`.
  Старые записи без этих полей дополняются скриптом автоматически.

## SM-2: как обновлять элемент после ответа

**1. Определи качество ответа `q` (0–5)** по тому, как пользователь справился:

| q | Что значит |
|---|---|
| 5 | мгновенно верно, без колебаний |
| 4 | верно после заминки / с мелкой помаркой |
| 3 | верно, но с трудом или после подсказки |
| 2 | неверно, но вспомнила, когда показал |
| 1 | неверно, лишь смутно знакомо |
| 0 | полный провал |

**2. Обнови повторения и интервал:**

```
если q >= 3 (верно):
    repetitions += 1
    если repetitions == 1: interval_days = 1
    иначе если repetitions == 2: interval_days = 6
    иначе: interval_days = round(interval_days * easiness_factor)
    consecutive_correct += 1;  consecutive_incorrect = 0
иначе (q < 3, ошибка):
    repetitions = 0
    interval_days = 1
    consecutive_incorrect += 1;  consecutive_correct = 0
```

**3. Обнови easiness_factor (EF):**

```
EF = EF + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))
EF = max(1.3, EF)
```

**4. Даты и mastery:**

```
last_seen = сегодня
due_date  = сегодня + interval_days
если consecutive_correct >= 3:
    mastery = min(5, mastery + 1);  consecutive_correct = 0
если consecutive_incorrect >= 3:
    mastery = max(0, mastery - 1);  consecutive_incorrect = 0
```

Серия **обнуляется после сдвига уровня**: каждый следующий mastery стоит новых трёх
верных подряд, а не одного. Без обнуления уровень рос бы на каждом ответе начиная с
третьего — шесть подряд давали бы mastery 4 и интервал в год. Практический счёт: чтобы
элемент дошёл до `mastery 2`, которого требуют ворота закрытия, нужно шесть верных
ответов, разнесённых интервалами SM-2.

Порог роста — **три** верных подряд, а не пять: пять подряд по одному элементу между
интервалами SM-2 практически не набирается, а критерий закрытия темы стоит на этой шкале.
Оговорка, чтобы не обмануться цифрами: нули в текущем `progress.json` — не следствие
порога. У всех 429 элементов `consecutive_correct: 0` и `last_seen: 1970-01-01`, то есть
`record` по ним не вызывался ни разу. Шкала оживёт по мере занятий, а не задним числом.

EF делает интервал индивидуальным: лёгкие для тебя элементы быстро уходят на длинные
паузы, трудные возвращаются часто.

## get_due — что пора повторить (для 40% спирали)

1. Элемент **due**, если `due_date <= сегодня`.
2. Приоритет выборки:
   1) активные паттерны ошибок с `next_review <= сегодня` (слабые места — вперёд);
   2) items с низким `mastery`;
   3) items с самой ранней `due_date`.
3. Возьми 2–4 элемента на ~40% комплекса и **вплети в задания по новой теме** (спираль),
   не отдельным блоком.
4. Если due-элементов нет — 1–2 с самым низким mastery, либо комплекс целиком на новом.

## База ошибок-паттернов (mistakes)

Отдельно от отдельных элементов фиксируем **повторяющиеся ошибки**, чтобы бить точечно.

При ошибке в разборе (см. checking.md):
1. Определи паттерн: категория (Словарный запас/Грамматика/Орфография/Тоны) + конкретика
   (например «тон в закрытом слоге, высокий класс»).
2. Если такой паттерн уже есть — `frequency += 1`, добавь новый пример
   `{your_answer, correct, context, date}`, обнови `last_occurred`.
3. Если новый — заведи запись со `status: active`, `frequency: 1`, первым примером.
4. Назначь `next_review` близко (например +1 день) — слабое место должно вернуться скоро.
5. Когда паттерн несколько занятий не всплывает и mastery связанных элементов растёт —
   переведи `status` в `resolved` (перестаёт тянуться в спираль, но история остаётся).

Паттерны — главный источник ответа на вопрос «что из старого я не помню».

## Состояния темы и закрытие

**Откуда берётся критерий.** Не сочиняется ни движком, ни ученицей: он уже написан в файле
темы. `import` читает его из секции «Тема закрыта, если ты можешь», а если её нет — из
«Резюме по теме», где список «К концу темы ты должна уметь» сформулирован именно как
действия. Так закрывающее испытание собирается по заявленным целям темы, а не по
случайному набору заданий из её лексики.

Тема — не мешок слов, а объект со своим состоянием. Без него спираль не знает, что можно
перестать подмешивать: «тема пройдена» означало бы «файл прочитан», а это не показатель
владения.

Состояния и переходы:

```
нет критерия ──импорт с exit-заданием──> в работе ──заявка──> на испытании
                                             ↑                     │
                                             │              два круга через интервал
                                    ошибка по теме                 ↓
                                             │                 закрыта
                                             └── вернулась <── две ошибки
```

| Статус | Что значит | Что делает движок |
|---|---|---|
| `no_criterion` | в файле темы не нашлось ни секции «Тема закрыта, если ты можешь», ни списка «должна уметь» в «Резюме по теме» | закрыть нельзя; сказать об этом прямо, не молчать |
| `in_progress` | обычная работа | тема в спирали в полном объёме |
| `testing` | один круг испытания пройден | второй круг — в другой день, не сегодня |
| `closed` | тема отпущена | из спирали уходит, переходит в редкий контроль |
| `returned` | откат после закрытия | входит в отработку по уронившему паттерну |

### Ворота закрытия

Семь условий, все обязательны. Первые четыре `close` проверяет по трекеру, остальные три
подтверждаются флагами — их нельзя вычислить из данных, это свойства самого листа.

1. **Пауза** — не меньше 7 дней с последнего занятия по теме. Считается по полю
   `last_lesson`, которое двигает **только** команда `lesson`. По `last_seen` элементов
   её считать нельзя: обязательная запись результатов через `record` обнуляла бы паузу
   сама, и ни один круг не засчитывался бы никогда.
2. **Ноль активных ошибок** с меткой этой темы — ни одного паттерна `active` или
   `critical`. Тема с висящей ошибкой не закрыта по определению.
3. **Порог по худшему элементу ядра**, не по среднему: `mastery ≥ 2` у каждого. Среднее
   прячет мёртвый хвост — шестьдесят сильных элементов и двадцать нулевых дают проходной
   балл при живой дыре.
4. **Результат испытания** — `--accuracy` не ниже **0.85**. Флаг обязателен при
   `--result ok`: закрывающее испытание есть частный случай контрольной, а у контрольных
   в `thai-learning` пороги 80% и 90%.
5. `--production` — не меньше **70%** заданий листа продуктивные (рус→тай, сборка,
   свободный ответ). Не полный запрет тай→рус: темы, чьё содержание рецептивно — буквы,
   гласные, тоны, чтение — иначе не закрыть вовсе, а покрытие темы обязательно.
6. `--no-hints` — подсказок не было. Использованная подсказка обнуляет попытку.
7. `--calibrated` — прогноз ученицы разошёлся с фактом **не больше чем на один пункт**.
   Одно число, один допуск: «совпала» без границы неисполнимо. Помеченные «не уверена»
   верные ответы на это условие не влияют — они стоят качества 3 своему элементу, и
   этого достаточно (см. `thai-mistakes`, «Закрывающее испытание темы»).

**Ядро темы** — правила и конструкции целиком плюс слова добором до 18 элементов;
размеченное вручную поле `core` в приоритете, и элементы чужих тем из него отбрасываются.
Порог считается по ядру, а не по всем восьмидесяти элементам: иначе тема не закроется
никогда, а хвост лексики и так живёт в SM-2 своей жизнью. Оговорка: `import` заводит
только слова (`type: word`) — правила попадают в трекер через `record --type rule`, и пока
их там нет, ядро состоит из одной лексики.

**Два круга.** Одного успешного испытания мало — нужно два, в **разные дни**. Отклонённая
попытка остаётся в `attempts` с полем `blocked_by`, но статус темы не меняет и к кругам не
идёт (`counted: false`). Сбой темы — ошибка, снятие с испытания, переоткрытие — гасит
засчитанные круги (`voided: true`): вернувшаяся тема проходит испытание заново, а не
дозакрывается одной попыткой.

**Что мешает закрыть.** `blockers` печатает **не больше трёх** пунктов: длинный список —
не список, а приговор. Решение о закрытии при этом принимается по **полному** набору, а не
по показанным трём, и каждый блокер имеет код (`pause`, `mastery`, `mistakes`, …) — отбор
жёстких условий идёт по коду, а не по тексту, иначе переформулировка молча ломала бы
закрытие.

### После закрытия

- тема уходит из `items_due` как источник собственных заданий;
- её лексика переезжает в отдельный ключ выдачи `due` — **`background`**: закрытая тема
  меняет роль, а не исчезает, и до 4 её элементов идут фоном в задания по другим темам.
  Иначе закрытие означало бы «забыть через полгода».
  **Кандидаты в фон — только те элементы закрытой темы, что уже подошли по SM-2**: срок
  проверяется до разделения на `items_due` и `background`, поэтому у темы, закрытой
  только что, фон может оказаться пустым — это нормально, слова вернутся, когда подойдёт
  их интервал. Из подошедших берутся 4 самых слабых: по `mastery`, при равенстве — по
  ранней `due_date`, тем же правилом, что и `items_due`. Порядок словаря сюда не годится:
  он повторяет порядок импорта, то есть фоном всплывали бы одни и те же первые слова
  темы, а забывается как раз хвост;
- переходит в редкий контроль: 90 → 180 → 365 дней (`next_control`). Пройденный контроль
  фиксируется тем же `close`: он двигает тему на следующую ступень лестницы. Проваленный
  (`--result fail`) возвращает её в работу;
- слова продолжают жить в SM-2 независимо от статуса темы. Закрывается умение, не лексика:
  одно слово может принадлежать двум темам, и закрытие первой не должно гасить вторую.

### Откат

Ошибка с меткой закрытой темы (через `mistake --topic`, `record` с качеством < 3 или
`attempt --result fail`): первая поднимает `suspicion` до 1 — тема под подозрением; вторая
переводит в `returned`. За одно занятие тема получает **не больше одного удара**: штатный
конвейер на один промах вызывает и `record`, и `mistake`, и без этого ограничения ступень
«под подозрением» была бы недостижима.

Вернувшаяся тема входит **не на старт**, а в отработку по тому паттерну, который её
уронил, — иначе цена отката так велика, что закрывать становится страшно. Причина отката
называется вслух: «вернулась из-за порядка слов, а не из-за лексики».

Ошибка по теме в статусе `testing` снимает её с испытания и возвращает в работу.

### Срок годности

`closed_at_difficulty` фиксирует уровень, на котором тема закрыта. Выросла
`meta.difficulty` — у темы появляется блокер `difficulty`, и она требует
переподтверждения: то, что сдано с опорой, не сдано в иммерсии.

## Авто-импорт лексики и правил из файлов

Чтобы get_due видел словарь темы, занеси его в трекер до генерации заданий.

1. Прочитай нужный файл (`glavaN_temaM_*.md` / `b1_glavaN_*.md`), секции «Словарный
   запас» и «Теория/конструкции».
2. Для каждого нового слова/правила добавь запись с `repetitions: 0, interval_days: 0,
   easiness_factor: 2.5, mastery: 0, consecutive_correct: 0, consecutive_incorrect: 0,
   due_date: сегодня` (сразу due) и `topic`. Транскрипцию бери из файла.
3. Не дублируй существующее. Примеры из «Практических упражнений» не импортируй.

Импорт делай тихо, до заданий.

## Регулятор сложности (1–10)

Сложность задаётся числом в `meta.difficulty` (по умолчанию **4** — уровень A2→B1).
Идея (из практики polyglot): по мере роста владения убираем подпорки, растёт когнитивная
нагрузка. Уровень управляет тем, **сколько опоры** даёт задание:

- **1–3 — перевод впереди.** Много русского, полная транскрипция ко всем тайским словам,
  короткие фразы. Пассивное узнавание.
- **4–6 — тайский с опорой.** Транскрипция только к новым/сложным словам, упор на
  продукцию рус→тай, простые конструкции.
- **7–10 — иммерсия.** Минимум транскрипции, длинные конструкции, перевод целых
  диалогов/текстов, работа с регистрами и идиомами (фокус B1 из её плана).

Команды пользователя «сделай сложнее / проще / хочу больше иммерсии» → измени
`meta.difficulty` и подстрой подачу. **Не меняй строгость проверки** — меняется только
объём опоры.

## Целевой процент успеха (desirable difficulty / i+1)

Держи сложность так, чтобы **свежие** (не повторные) задания давали ~**60–70%** успеха —
это зона максимального обучения: трудно, но достижимо.

- Считай `meta.recent_accuracy` по последним занятиям (доля верных на новом материале).
- Если стабильно **> 80%** — подними `meta.difficulty` на 1.
- Если **< 50%** — опусти на 1 и добавь больше опоры/разминки.
- 60–70% — не трогай, идёшь оптимально.

Это калибрует регулятор сложности сам, а не на глаз.

## Обновление после занятия и обзор прогресса

После разбора обнови по каждому задействованному элементу SM-2 (выше), запиши ошибки в
`mistakes`, пересчитай `meta.recent_accuracy`, поставь `meta.updated = сегодня`.

Команда «покажи прогресс» → собери из `progress.json` короткий обзор (без геймификации):

```
Прогресс — тайский · сложность 4 · точность (новое): 68%

Темы (медиана mastery по ядру):
  6.1        ⭐⭐⭐☆☆  (3/5 по ядру из 18, 52 эл.) — в работе
  6.1.2      ⭐⭐☆☆☆  (2/5 по ядру из 11, 11 эл.) — нет критерия
  3.4        ⭐⭐⭐⭐☆  (4/5 по ядру из 18, 80 эл.) — закрыта
Закрыто: 3.4

Пора повторить (due): 5 элементов
Активные слабые места:
  • Тоны: закрытый слог, высокий класс — 3×
  • Грамматика: порядок слов в вопросе — 2×
```

Файл машинный — не засоряй прозой; источник правды для спирали — `progress.json`.
