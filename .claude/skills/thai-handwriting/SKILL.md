# Thai Handwriting Skill

Распознавание тайского на картинке — это **не одно действие, а конвейер**. Модель, которая
смотрит на фото тетради целиком, читает хуже, чем та же модель, которая смотрит на одну
строку крупным планом и потом проверяет прочитанное по правилам орфографии.

Главное правило скилла: **никогда не «дописывать» слово до знакомого**. Если штрихи не
подтверждают букву — она помечается как неуверенная, а не заменяется правдоподобной.
Выдуманное чтение в учебном проекте хуже, чем честное «здесь не разобрать».

## Инструмент

`scripts/thaiocr` — офлайн-CLI на встроенных macOS-фреймворках (Vision + CoreImage).
Ничего не устанавливает, в сеть не ходит. Собирается сам при первом запуске.

```bash
S=.claude/skills/thai-handwriting/scripts/thaiocr

$S lines фото.jpg /tmp/th --scale 4 --words-from progress.json   # нарезать на строки
$S ocr   фото.jpg --words-from progress.json                     # OCR всей страницы
$S prep  фото.jpg /tmp/clean.png --deskew --mono --scale 2       # почистить и выпрямить
$S crop  фото.jpg /tmp/zoom.png --rect 400,120,300,90 --scale 6  # приблизить фрагмент
$S langs                                                         # проверить, что th-TH жив
```

`scripts/lookup.py` — подбор кандидатов по неуверенно прочитанному слову: ищет по
`progress.json` и по всей лексике учебных материалов.

```bash
python3 .claude/skills/thai-handwriting/scripts/lookup.py "?ับ"      # буква не разобрана
python3 .claude/skills/thai-handwriting/scripts/lookup.py "[กถ]ิน"   # выбор внутри пары
```

`scripts/typhoon.py` — **второй OCR-движок** (Typhoon OCR 1.5 через локальный Ollama,
офлайн). Независимое от Vision чтение для перекрёстной проверки.

```bash
python3 .claude/skills/thai-handwriting/scripts/typhoon.py страница.jpg   # вся страница
python3 .claude/skills/thai-handwriting/scripts/typhoon.py --compare /tmp/th  # Vision vs Typhoon
```

Замерено, что **на этом почерке Typhoon слабее Vision** (см. `calibration.md`): галлюцинирует
на узких полосках, путает ฉัน→นั่น, нестабилен. Использовать только как **сигнал согласия** —
совпали два движка на слове → уверенно; разошлись → смотреть глазами. Никогда не брать
чтение Typhoon как истину. Гонять на **всей странице**, не на `line-*.png`.

Что важно знать про встроенный OCR:

- Vision распознаёт `th-TH` **уверенно на печати** и **ненадёжно на рукописи**. Он —
  второе мнение, не источник истины. Источник истины — твои глаза на увеличенной строке.
- `--words-from progress.json` подсказывает Vision словарь пользователя (ключи `items`).
  Заметно поднимает точность на пройденной лексике. Работает и с обычным `.txt`
  (по слову в строке).
- Если Vision вернул пусто, `lines` всё равно нарежет лист на горизонтальные полосы
  (`--bands N`) — читать глазами можно и без его помощи.
- `--pad-y` (по умолчанию 0.35) — запас сверху и снизу. Тайская строка выходит за базовый
  bbox: сверху тоновые знаки и ◌ี ◌ื, снизу ◌ุ ◌ู и хвост ฏ ฎ. **Не уменьшай его** —
  срезанный тоновый знак означает потерянный тон.

## Когда скилл вообще работает

**Единственный источник материала — папка `Handwriting/`, и только файлы за сегодня.**
Картинка в сообщении — не команда на распознавание: пользователь часто вставляет обычные
скриншоты, и запускать на них конвейер неверно. Первое действие — не чтение картинки, а
проверка папки:

```bash
find Handwriting -maxdepth 1 -type f ! -name README.md -newermt "$(date +%F)"
```

| Что в папке | Что делать |
|---|---|
| Есть файлы за сегодня | Конвейер по ним. Разбирать **только эти файлы**, не встроенную в сообщение картинку |
| Пусто, а в чате фото рукописи | Конвейер не запускать. Предложить `intake` (см. ниже); файл ляжет в папку — тогда работать по нему |
| Пусто, а в чате обычный скриншот | Скилл не нужен: ответить по существу вопроса без распознавания |
| Только файлы прошлых дней | Считать, что папки нет: это остаток закрытой сессии. Перед новой работой — `scripts/clean` |

Из этого следует и обратное: **если файлы за сегодня в папке лежат, разбирать надо их**, —
даже если в текущем сообщении картинки нет вовсе («проверь домашку», «что я написала»).

## Как фото попадает в папку

`thaiocr` работает с файлом на диске. Картинка, **вставленная прямо в чат**, файлом на
диске не становится — она приходит встроенной в сообщение, пути у неё нет, и восстановить
исходные байты из того, что видно, нельзя.

Мост — **буфер обмена**. Когда пользователь вставляет фото по Cmd+V, оно остаётся в буфере.
`scripts/intake` вытаскивает его оттуда в `Handwriting/` и сразу режет на строки:

```bash
.claude/skills/thai-handwriting/scripts/intake        # из буфера обмена
.claude/skills/thai-handwriting/scripts/intake файл…  # из указанных файлов
```

`intake` из буфера сохраняет лучший формат: скопирован **файл** (Cmd+C в Finder) → оригинал
без потерь (HEIC/JPG как есть); скопировано **содержимое** (Cmd+V фото) → JPEG с EXIF; иначе
PNG. Аргументом принимает heic/jpg/jpeg/png. `thaiocr` читает HEIC напрямую, конвертация не
нужна.

Порядок действий, когда в чате фото рукописи, а в папке за сегодня пусто:

1. **Запустить `intake`** — он поднимет картинку из буфера в `Handwriting/` и нарежет
   строки в `Handwriting/.lines/<имя>/`. Дальше — обычный конвейер по строкам.
2. Если буфер пуст (фото затащили в чат мышью, а не через Cmd+V) — `intake` это скажет.
   Тогда попросить **перетащить файл на папку `Handwriting/`** в проводнике VS Code (один
   жест, получается настоящий файл) либо скопировать фото в буфер и повторить.
3. **Читать встроенную в сообщение картинку вместо файла — нельзя.** Пока файла в папке
   нет, распознавания нет: скажи, что фото не доехало до `Handwriting/`, и попроси
   повторить одним из двух способов выше. Чтение «на глаз» без нарезки даёт худшее
   качество ровно там, где цена ошибки максимальна, — и именно оно ломает разбор.

Фильтры, словарь и формат ответа применяются в любом случае — они от инструмента не зависят.

## Конвейер

### 1. Подготовить

Фото тетради со стола почти всегда требует чистки:

```bash
$S prep фото.jpg /tmp/clean.png --deskew --scale 2
```

`--deskew` выравнивает наклон по медиане строк, `CIDocumentEnhancer` (включён по умолчанию)
убирает тень и вытягивает штрих, `--mono --contrast 1.6` добивает бледный карандаш.
Скриншотам и уже ровным сканам предобработка не нужна — работай с оригиналом.

### 2. Нарезать на строки и посмотреть на каждую

```bash
$S lines /tmp/clean.png /tmp/th --scale 4 --words-from progress.json
```

Дальше — читать `line-01.png`, `line-02.png` … **по одной, инструментом Read**. Это
ключевой шаг: одна строка, увеличенная в 4 раза, читается несопоставимо лучше, чем
страница целиком, где буквы съедаются масштабированием.

`lines.json` рядом хранит догадку Vision по каждой строке с уверенностью и альтернативами.

### 3. Сверить два чтения

| Ситуация | Что делать |
|---|---|
| Глаза и Vision совпали | Принять чтение |
| Расходятся в одном слове | `crop` этого места с `--scale 6`, посмотреть вблизи |
| Vision молчит (рукопись) | Читать глазами, опираться на `references/letterforms.md` |
| Оба не уверены | Пометить `[?]` и спросить пользователя |

### 4. Пропустить через фильтры

Прежде чем показать результат — проверить каждое слово по `references/disambiguation.md`:
допустима ли такая финаль, на месте ли предпозиционная гласная, над той ли буквой тоновый
знак, есть ли слово в словаре проекта. Фильтры ловят большую часть ошибок распознавания
раньше пользователя.

### 5. Показать результат

## Формат ответа

Сначала — что написано, потом — комментарии. Не смешивать.

```
Строка 1:  ฉันตื่นนอนตอนเจ็ดโมงเช้า
Строка 2:  เขาไปตลาด[ก?]ับเพื่อน
Строка 3:  วันนี้อากาศร้อนมาก
```

Затем — разбор только там, где есть что сказать:

> **Строка 2, «ก?»** — петля не замкнулась, читается и как ก, и как ถ. Взял ก: กับ
> «с, вместе с» — обычное слово, ถับ в словаре нет.

Обозначения:

- `[ก?]` — прочитано, но неуверенно; в скобках наиболее вероятный вариант
- `[ก/ถ]` — два равновероятных чтения, выбрать не удалось
- `[…]` — не разобрать вообще

Уверенность указывать словами (высокая / средняя / низкая), а не процентами — процент
у распознавания на глаз всё равно вымышленный.

## Проверка рукописной домашней работы

Если пользователь прислал **свою** работу, а не чужой текст, разделяй два слоя:

1. **Почерк** — буква написана неузнаваемо, петля не в ту сторону, тоновый знак не над той
   согласной, гласная ◌ิ съехала вправо, слипшиеся слова. Это дефект письма.
2. **Язык** — орфография, тон, грамматика, лексика. Это дефект знания.

Сначала подтверди, что именно ты прочитал («вижу: ...»), и только потом разбирай. Иначе
разбор поедет по неверно распознанному слову — самая дорогая ошибка в этом сценарии.

Ошибки почерка, которые повторяются, стоит записать в трекер как паттерн:

```bash
python3 .claude/skills/thai-tasks/scripts/tracker.py mistake progress.json "почерк_петля_ถ" \
  --category Орфография --your "ก" --correct "ถ"
```

Разбор языковых ошибок — не здесь: за него отвечает `thai-learning`
(+ `thai-tasks/references/checking.md`), оформление слов — `thai-display`,
транскрипция — `thai-phonetics`.

## Очистка папки Handwriting/

Рабочая папка копит исходные фото, `.lines/`, `.zoom/`, временные кропы — вручную это
чистить не нужно. Есть скрипт, который сносит всё в `Handwriting/` **кроме `README.md`**
(и ничего вне папки не трогает — путь берётся от расположения скрипта):

```bash
.claude/skills/thai-handwriting/scripts/clean            # почистить
.claude/skills/thai-handwriting/scripts/clean --dry-run  # показать, что удалится
```

**По команде.** Пользователь пишет **«clean photo»** (или «почисти фото», «убери фото»,
«clean») — сразу запусти `scripts/clean`. Отдельного фото в сообщении для этого не нужно.

**Автоматически (рекомендованный дефолт).** Чисти **на границе новой работы**: когда
приходит новое, не связанное с предыдущим фото/домашка — первым делом `scripts/clean`,
затем `intake`. Отдельный повод — файлы прошлых дней: они уже не считаются материалом
(триггер смотрит только на сегодняшние), так что снести их при старте новой работы. Это держит папку в размере одной сессии без единого действия пользователя.
**Не чисти** между кадрами одной пачки (многостраничная домашка) и во время уточняющих
вопросов по текущему фото — там `.lines/` и кропы ещё нужны для повторного взгляда.

## Чего не делать

- Не запускать конвейер на всякой картинке из чата. Триггер — файлы за сегодня в
  `Handwriting/`, а не факт того, что в сообщении есть изображение. Скриншот интерфейса,
  мем, страница сайта — обычный ответ без скилла.
- Не подменять файл из папки встроенной в сообщение картинкой, даже если это «то же самое
  фото»: у встроенной нет пути, нарезки и увеличения, а значит и точности.
- Не выдавать чтение без пометок, если сам не уверен. Тихая догадка ломает учебный цикл.
- Не доверять Vision на рукописи только потому, что он выдал уверенность 1.00 — на
  рукописном тайском его калибровка не работает.
- Не подгонять прочитанное под ожидаемую тему урока. Пользователь мог написать не то, что
  ты ждёшь, — в этом и смысл проверки.
- Не читать страницу целиком, если строки можно нарезать. Это главная причина ошибок.
- Не выводить в статусе техническую кухню конвейера (предобработка, нарезка на строки,
  уверенность Vision, номера строк, параметры скриптов). Пока идёт распознавание — короткий
  нейтральный статус вроде «Проверяю фото», без подробностей. Все детали — только в
  финальном отчёте по формату выше, и то лишь там, где есть что сказать.
- Не восстанавливать тоны по памяти при разборе: тон сверяется по авторитетному источнику,
  как и везде в проекте.

## Справочные файлы

- `references/letterforms.md` — рукописные формы: петля-หัว, крючок вверху справа, группы
  путаницы, диакритика, «беспетельный» почерк.
- `references/disambiguation.md` — орфографические фильтры: допустимые финали, позиции
  гласных и тоновых знаков, проверка по словарю проекта.
- `references/calibration.md` — **читать первым**: особенности почерка этого ученика,
  известные систематические ошибки Vision на нём, рабочие параметры нарезки.
