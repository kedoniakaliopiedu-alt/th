## Что взято

Кода здесь нет — взята **архитектура процесса**:

- **step-file architecture** — по одному файлу на шаг, загружается строго по одному,
  состояние во фронтматтере шага, обязательные остановки на чекпойнтах;
- **каскад поиска цели ревью** (`steps/step-01`) — от явного аргумента через недавний
  диалог и состояние git к прямому вопросу, с остановкой на первом сработавшем уровне;
- **параллельные слепые слои** (`steps/step-02`) — подагенты без контекста разговора,
  запуск разом, обработка отказа слоя без остановки всего ревью;
- **структурированный триаж** (`steps/step-03`) — нормализация → дедуп по «то же
  утверждение И то же действие» → **чтение файла до присвоения важности** → важность по
  последствию для конечного потребителя → маршрутизация в один из четырёх сегментов;
- **порядок разбора** (`steps/step-04`) — сначала то, что требует решения человека, потом
  правки; отложенное копится в отдельный файл с причиной.

## Что переписано под этот проект

- **Слои ревью** (`references/review-layers.md`) написаны заново. Оригинал ревьюит код и
  делегирует линзы скиллу `bmad-review`; здесь ревьюются markdown-инструкции, учебные файлы
  и вспомогательные скрипты, а линзы заданы прямо в файле — их можно править, не трогая шаги.
  Слои «границы скиллов» и «методический аудитор» существуют только здесь.
- **Роль спеки** играет не story-файл, а связка `AGENTS.md` + `.codex/skills/MAP.md` +
  `description` самого скилла; необязательный `{intent_file}` — лист правок из
  `skill-brainstorm`.
- **Шкала важности** привязана к последствиям для ученицы, а не для пользователя софта.
- Убраны sprint-status, story-статусы и вся инфраструктура BMAD (`_bmad/`, `customize.toml`,
  `resolve_customization.py`). Отчёты пишутся в `.codex/reviews/`.
- Добавлен режим `scope = skill` — аудит скилла целиком, а не только диффа.
